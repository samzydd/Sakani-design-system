# Sakani Design System

A token-driven React component library, built to match its source Figma file
1:1 — every color, spacing value, radius, and shadow comes from a CSS custom
property, never a hardcoded value, and every component ships with a working
light and dark theme out of the box.

## What's in here

This Storybook is organized into two layers, browsable from the sidebar:

**Components** — the reusable primitives (`Button`, `Input`, `Select`,
`Badge`, `Avatar`, and everything else under Core, Forms, Navigation,
Overlays, Data, Charts, Application, E-commerce, and Marketing). These map
1:1 to Figma component sets — each prop corresponds to a real Figma variant
axis, and every state (hover, focus, error, disabled, loading…) is either a
CSS pseudo-class or a typed prop, matching how the design was actually built.

**Blocks** — full page sections assembled from those components (under
Application, Authentication, Billing, Chat, Data & Content, E-commerce, and
Marketing). Every block's own file starts with a doc comment marked **A
COMPOSITION EXAMPLE, not a configurable component** — blocks are meant to be
copied into your project and edited directly, not imported as a black box.
Open any block's source to see exactly which primitives it's built from and
why.

## The token system

All visual values live in `tokens.css` as CSS custom properties, layered two
levels deep:

- **Primitives** — raw values with no meaning attached (`--color-neutral-900`,
  `--space-16`, `--radius-md`). Never referenced directly by components.
- **Semantic tokens** — the ones components actually use (`--color-fg-default`,
  `--color-bg-surface`, `--color-border-subtle`). Each one points at a
  primitive, and that mapping flips per theme — the same semantic token
  resolves to a different primitive in light vs. dark mode, which is the
  whole mechanism dark mode runs on. Toggle it with the sun/moon control in
  the toolbar above.

Typography runs on Geist (`@fontsource-variable/geist`), loaded once in
`.storybook/preview.tsx`.

## Reading a component's docs page

Every component and block's Docs page (like this one, but for something
with actual controls) opens with a written explanation of what it is, what
it maps to in Figma, and any non-obvious implementation decisions — pulled
straight from that component's own source file. Below that: a live,
interactive preview, a full props table, and every documented story/state.
Use the **Controls** tab to try different prop combinations against the
real component, not a static screenshot.

## Using this outside Storybook

This library ships as `@sakaniui/react` — import components directly:

```tsx
import { Button, Badge, Avatar } from '@sakaniui/react';
import '@sakaniui/react/style.css';
```

Blocks live at a separate entry point and are meant to be copied, not
imported as-is — open the block's source under `src/blocks/` in this repo,
copy the file into your project, and edit the sample data/callbacks for
your own use case.
